# Правила GML для LimeUI

## Именование

- Конструкторы компонентов — `PascalCase` с префиксом `Lui`, например `LuiButton`.
- Публичные методы — `camelCase`, например `setText()` и `getStyle()`. Внутренние методы — `_camelCase`, например `_calcIconSize()`.
- Поля — `snake_case`. Для новых внутренних полей использовать префикс `_`, например `_cached_style`.
- Параметры и локальные переменные — `_snake_case`, например `_available_width`. Короткие индексы циклов вроде `i` допустимы без префикса. Существующие параметры сохраняют свои имена.
- Макросы и константы событий LimeUI — `UPPER_SNAKE_CASE` с префиксом `LUI_`, например `LUI_AUTO` и `LUI_EV_SIZE_UPDATE`.

## Форматирование

- Использовать табы для отступов. Открывающую `{` ставить на той же строке. Ветки `else` и `else if` писать в форме `} else {` и `} else if ... {`.
- Простые условия `if` писать без внешних круглых скобок. В сложных выражениях использовать скобки для явной группировки.
- Однострочные `if` использовать только для `return` и `continue`. Во всех остальных случаях писать блок с фигурными скобками и переносами строк.
- Ставить `;` после обычных инструкций. Объявления методов вида `static name = function(...) { ... }` и `self.draw = function() { ... }` завершать закрывающей `}`.
- Разделять логические блоки пустыми строками. В больших конструкторах обозначать разделы короткими комментариями вроде `// GETTERS` и `// RENDER`.

```gml
if self.is_destroyed return self;

if self.has_focus && (_pressed || _released) {
	self._dispatchEvent(LUI_EV_KEYBOARD_INPUT);
}
```

## Язык комментариев

**Все комментарии в коде писать на английском языке.** Это касается обычных комментариев, заголовков разделов, `TODO` и текста JSDoc.

## Документация API

- Документировать публичный API в формате GML JSDoc. Использовать `///@desc`, `///@arg` и `///@return` по необходимости. Для аргументов всегда использовать `@arg` вместо `@param`.
- В описании конструктора перечислять поддерживаемые ключи `_params`. Для внутренних методов, которые нужно исключить из документации, использовать `///@ignore`.

## Структура компонентов

- Организовывать каждый конструктор по секциям в таком порядке: состояние и параметры, публичный API, внутренние методы, обновление и отрисовка, обработчики событий. Использовать короткие английские заголовки, например `// STATE`, `// PUBLIC API`, `// INTERNALS`, `// UPDATE AND DRAW` и `// EVENT HANDLERS`. В коротких конструкторах пропускать пустые и избыточные секции.
- Группировать поля и методы по назначению. В публичном API держать связанные геттеры, сеттеры и действия рядом. У каждого конструктора в общем файле должна быть собственная структура.
- В крупных классах вроде `LuiBase` и `LuiMain` выделять отдельные секции для жизненного цикла, обновления кадра и рендера, а внутренние методы группировать по подсистемам: Flex, стили, ввод, модальные окна, кеши и другие. Вспомогательную отладочную отрисовку размещать ближе к концу файла.
- При переносе блоков сохранять порядок исполняемой инициализации и регистрации обработчиков событий. Захватывать базовый метод через `method(...)` до переопределения соответствующего метода.

- Оформлять виджеты как GML-конструкторы с наследованием. Инициализировать поля состояния и значения по умолчанию в начале конструктора. Для необязательных параметров использовать шаблон `_params[$ "text"] ?? ""`.
- Общие методы объявлять через `static name = function(...)`. Переопределяемые обработчики вроде `draw`, `update` и `destroy` объявлять через `self.name = function(...)` по контракту компонента.
- Обращаться к полям и методам текущего элемента через `self`, например `self.text` и `self._calcIconSize()`. В обработчиках событий обращаться к переданному элементу через `_e`, например `_e._calcIconSize()`.
- Сеттеры, предназначенные для цепочек вызовов, возвращают `self`. Геттеры и операции вроде `animate()` возвращают результат согласно своему контракту.
- Разделять обновление состояния и отрисовку. Пересчёты, связанные с созданием элемента или изменением размера, привязывать к соответствующим событиям. В `draw()` брать действующий стиль через `self.getStyle()` и учитывать `draw_get_alpha()`.
